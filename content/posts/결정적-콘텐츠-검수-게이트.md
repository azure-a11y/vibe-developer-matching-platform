## 검수 게이트는 규칙 기반 함수 하나다

Orca AI Company에서 글 하나가 발행 가능한지 판단하는 로직은 `packages/content/src/audit.ts`의 `auditPost()` 함수 하나에 들어 있다. 모델을 호출하지 않는다. admin 검수 화면과 `pnpm audit:content` CLI가 같은 함수를 부르기 때문에, 사람이 보는 결과와 에이전트가 보는 결과가 항상 일치한다.

## 네 개의 lane

이슈는 네 가지 lane으로 나뉜다.

- **editorial** — 본문 길이, 헤딩 구조, description 존재 여부
- **seo** — 제목·설명 길이, 키워드, 태그, canonical·OG 이미지 형식
- **geo** — answerSummary, FAQ, entities, citations
- **images** — 커버 이미지의 alt 텍스트와 출처(provenance)

각 lane은 admin 검수 화면에서 별도 체크박스로 표시되어, 사람이 어느 영역을 확인했는지 남길 수 있다.

## error와 warn을 나누는 기준

기준은 하나다. "규칙만으로 확실히 틀렸다고 말할 수 있는가." 예를 들어 커버 이미지에 alt 텍스트가 없으면 접근성과 SEO 모두에 명백히 문제가 있으므로 error다. 반면 본문이 600자보다 짧은 것은 품질 신호일 뿐 확정적인 오류가 아니므로 warn에 그친다.

## 점수는 100에서 깎아 내려간다

`score = 100 - errors * 20 - warnings * 7`. error 하나면 80점, warn 하나면 93점이다. 점수 자체는 참고용이고, 발행 가능 여부를 실제로 결정하는 값은 `publishable = errors === 0`이다. 점수가 아무리 높아도 error가 하나라도 남아 있으면 발행 버튼은 비활성화된다.

## 에이전트가 자기 글을 발행할 수 없는 이유

`blog-writer` 에이전트의 절대 규칙 중 하나는 `status`를 `published`로 바꾸지 않는 것이다. 종착점은 `in_review`까지다. 발행은 admin 검수 화면에서 사람이 `review.checks` 여섯 항목을 확인한 뒤 누르는 행위로 남겨둔다. 이 글도 마찬가지로 `in_review` 상태로 저장되어 있다.

## 직접 돌려보기

```bash
pnpm audit:content 결정적-콘텐츠-검수-게이트
```

error 없이 warn만 몇 개 남아 있다면 정상이다. 이 글에는 커버 이미지와 citations가 없는데, 둘 다 `info` 등급이라 발행을 막지 않는다.
