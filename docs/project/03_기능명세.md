# 03. 기능명세 — 화면 단위 재편

> 작성일 2026-08-14 · 상태: 초안(v1) · 소스: `docs/planning/AI빌더그룹_PRD.md`(v4) §4 FR-1~10
> PRD의 FR은 이미 Given/When/Then을 갖추고 있다. 이 문서는 새로 작성하지 않고 **화면 단위로 재배치**만
> 한다. FR 번호·AC 번호는 PRD와 동일하게 유지해 상호 참조가 끊기지 않게 한다. 카피·발행·권한 관련
> 정책성 내용은 `04_정책정의.md`로 넘겼다.

---

## 1. 홈 (FR-1)

**목적**: 첫 화면에서 3사 소개 없이 "바이브 코딩 외주" 메시지를 즉시 전달.

- AC-1.1 신규 방문자가 첫 화면(above the fold)을 로드하면, 3사 소개 없이 핵심 메시지가 즉시 노출된다.
- AC-1.2 스크롤 시 섹션마다 서로 다른 인터랙션이 적용되고, 일부 섹션은 의도적으로 애니메이션 없음(딸깍 방지 판단 기준).
- AC-1.3 CTA "문의하기" 또는 "Work 보기" 클릭 시 각각 FR-4·FR-2로 이동하고 GA 클릭 이벤트 전송(FR-8).
- AC-1.4 어떤 카피든 "저렴함"을 소구하지 않는다(`04_정책정의.md` §1).
- AC-1.5 1차 CTA는 "VIEW WORK PORTFOLIO"(Work 섹션 이동), "프로젝트 문의하기"는 상단 nav + 상세 모달의 상시 CTA로 배치(진입점만 재배치, 목적지는 AC-1.3과 동일).

## 2. Work — 포트폴리오 (FR-2)

**목적**: 실제 수행 프로젝트로 신뢰를 판단하게 하고, 참여 빌더로 연결.

- AC-2.1 프로젝트 카드는 실제 수행 프로젝트만 노출(목업/가상 사례 금지 — `04_정책정의.md` §2).
- AC-2.2 참여 빌더 영역 클릭 시 해당 빌더 프로필(FR-7)로 이동.
- AC-2.3 Work 콘텐츠 소스가 런칭 시점까지 미확정(Q4)이면 "준비 중" 빈 상태로 노출 가능해야 한다 (콘텐츠 0건이 배포 블로커가 되면 안 됨).
- AC-2.4 목업 기준: 카드 클릭 시 별도 페이지 대신 빌더 상세 프로필이 모달로 노출(경력·프로젝트 수·위치·상태·작업 방식 요약·포트폴리오 갤러리). FR-7의 상당 부분이 이 모달에 흡수된 형태 — FR-7을 이 모달로 대체할지, 별도 페이지를 병행할지는 **Q17 미확정**.
- AC-2.5 현재 목업 데이터는 전부 샘플/플레이스홀더 — AC-2.1은 아직 충족 안 됨, M2 콘텐츠 확정 시 실데이터 교체 필요.
- AC-2.6 상세 페이지 컴포넌트에 "AI스러운 느낌"이 남아있다는 피드백(Q19 미확정) — 추가 고도화 필요.

## 3. Insight — 콘텐츠/블로그 (FR-3)

**목적**: 카테고리별 콘텐츠 발행, 빌더 작성 글 → 빌더 프로필 연결.

- AC-3.1 카테고리 필터 적용 시 "일하는 방식 / AI 활용 공유회 / 빌더가 쓴 글"로 재구성된 카테고리로 필터링.
- AC-3.2 작성자 영역 클릭 시 해당 빌더 프로필(FR-7)로 이동.
- AC-3.3 유튜브 링크 클릭 시 UTM 파라미터가 부여되어 유튜브 스튜디오에서 전환 추적 가능.
- AC-3.4 유튜브 탭 배치(A5)는 **해소됨** — 완전히 분리된 Eduinfo 섹션(FR-9)으로 이동. Insight는 블로그형 아티클만 다룬다.
- AC-3.5 (참고) 목업의 Insight 상세는 카드 6건 클릭 → 모달.
- AC-3.6 **Q15 미확정**: 모달 UI는 고유 URL이 없어 검색엔진 색인 불가 — FR-8 AC-8.3(SEO)과 상충 가능. 실제 구현 시 개별 글마다 라우팅된 정적 페이지 + 모달은 프리뷰 용도로만 남길지 결정 필요.

## 4. Eduinfo — 교육 콘텐츠 (FR-9)

**목적**: 이솝 님 강의 영상 + PDF 자료로 유튜브 채널 유입과 브랜드 신뢰 확보.

- AC-9.1 강의 목록(목업 기준 10편) · 선택된 강의의 유튜브 임베드 플레이어 · 관련 PDF 자료 요약이 한 화면에 노출.
- AC-9.2 강의 목록에서 항목 선택 시 임베드/PDF 요약이 갱신되고, 유튜브 원본 채널로 이동하는 새 탭이 전환 애니메이션과 함께 열린다.
- AC-9.3 "PDF 자료 다운로드"는 **Q13 미확정** — 현재 목업은 안내 문구만(placeholder), 실제 파일/스토리지 연동 필요.
- AC-9.4 유튜브 채널 연동은 **Q14 미확정** — 공식 채널 확정되면 샘플 검색 링크를 실제 재생목록으로 교체.

## 5. 문의하기 — pluug 연동 (FR-4) ⭐ 핵심

**목적**: 리드를 pluug(CRM)로 전달해 사람이 직접 배정받게 함(자동 매칭 아님 — 고단가 외주 특성).

- AC-4.1 필수 항목 입력 후 제출 시 리드가 pluug로 전달되고 제출 완료 화면/메시지 노출.
- AC-4.2 pluug 연동 방식(API/임베드/리다이렉트)은 **Q7/Q20 부분 미확정** — 착수 전 똑똑한 개발자 기존 연동 사례를 기술 분석해 방식과 계정·API 키 제공 주체를 먼저 확정.
- AC-4.3 문의 전환을 잠식할 수 있는 다른 CTA(예: 소개서 다운로드) 신규 배치 시 GA 전환 추이를 배포 전후로 비교 검증(실측 사례: 버튼 하나로 주 10~20건→0건, `04_정책정의.md` §1 근거).
- AC-4.4 폼 제출 완료 시 GA 이벤트 전송(FR-8 연동).
- AC-4.5 목업 기준: 상단 nav + Work 카드 상세 모달의 "프로젝트 문의하기" 두 곳에서 동일한 모달형 폼(이름/회사/연락처/프로젝트 유형 select/메모). 현재는 클라이언트 측 성공 메시지만, pluug 실연동은 미구현.
- AC-4.6 2차 미팅 결정: 우선 임의 pluug 계정으로 폼을 연동해두고, 관리자(FR-5)에서 폼 링크(URL)를 교체하면 공개 사이트에 즉시 반영. 정식 pluug 프로덕션 계정 연동은 클라이언트가 추후 처리. 최종 연동 방식은 여전히 미확정(Q7/Q20).

## 6. 빌더 프로필 (FR-7) — IA만, 기능은 백로그

**목적**: 참여 프로젝트·작성 콘텐츠·일하는 방식 요약을 한 페이지에서 노출, "이력서"로 쓰임.

- AC-7.1 참여 프로젝트 목록·작성 콘텐츠 목록·일하는 방식 한 줄 요약 영역을 포함한 와이어프레임 제공.
- AC-7.2 3주 범위(Q8)상 IA·와이어프레임까지만 v1 포함, 실제 기능(자산화 PDF, AI 추천 매칭)은 백로그.
- AC-7.3 "포트폴리오 없는 신규 빌더가 AI 추천에서 후순위로 밀리는" 리스크를 인지한 상태로 화면 구조 설계.
- ⚠️ FR-2 AC-2.4(Work 상세 모달)와의 관계는 **Q17 미확정** — 이 화면이 별도 페이지로 남을지, 모달로 완전히 흡수될지 결정 필요.

## 7. 전역 — SEO · GA 트래킹 (FR-8)

**목적**: 버튼/메뉴 단위로 전환 기여도를 데이터로 확인.

- AC-8.1 옵션 클릭에 따라 화면이 전환되는 UI(예: FAQ)는 단순 화면 전환이 아니라 URL 슬러그가 바뀌어야 GA로 유입 경로 구분 추적 가능(예: `/faq/aiax` ↔ `/faq/it`).
- AC-8.2 주요 CTA 버튼에 요소 단위 클릭 이벤트가 GA에 태깅.
- AC-8.3 구글·네이버 기준 메타태그/사이트맵/소유확인 등 기본 테크니컬 SEO 세팅 완료(GEO/AEO 별도 대응 없음).
- AC-8.4 **Q16 미확정**: 목업 FAQ는 카테고리 구분 없는 5문항 단일 아코디언 — AC-8.1의 슬러그 분기는 실제 개발 시 별도 설계 필요.

## 8. 관리자 · Insight 관리 (FR-5)

- AC-5.1 관리자 로그인 후 Insight 관리 화면에서 글 목록/작성/수정/카테고리 지정.
- AC-5.2 매칭 기능·리드 관리는 관리자 화면에 포함하지 않는다(리드는 pluug 전담).
- AC-5.3 pluug 폼 링크(URL)를 조회·수정할 수 있는 설정 필드 포함 — 변경 시 공개 사이트 문의하기(FR-4)에 즉시 반영.

## 9. 관리자 · 빌더/프로젝트 승인 (FR-6)

- AC-6.1 빌더가 프로젝트 업로드 시 상태 "승인 대기"로 등록, Work(FR-2)에 즉시 노출 안 됨.
- AC-6.2 최종 관리자 승인 시 상태 "공개"로 전환되어 Work 목록에 노출.
- AC-6.3 관리자가 빌더 계정 목록에서 활성/비활성 상태 확인·변경 가능.
- AC-6.4 빌더별 Insight 작성/수정/삭제 권한을 관리자가 개별 토글(기본값: 본인 Work 업로드만 허용, 삭제는 기본 비활성). 권한과 무관하게 Work·Insight는 항상 승인/검수 대기로 등록, 공개 전환은 최종 관리자만 가능(`04_정책정의.md` §3 발행 게이트와 동일 원칙).

## 10. 관리자 · 계정·권한 (FR-10)

- AC-10.1 최종 관리자가 "계정·권한" 화면에서 관리자 계정 생성(초대 이메일) + 등급 지정.
- AC-10.2 등급별 메뉴 접근 권한 매트릭스(대시보드/Builder/Work/Work Process/Insight/설정/계정·권한 7개, 전체/편집·승인/조회/접근불가).
- AC-10.3 빌더별 권한 토글 변경 시 해당 빌더 로그인 화면에 그 권한만큼만 메뉴 노출(삭제 기본 비활성).
- AC-10.4 로그인이 필요한 화면은 전용 로그인(이메일·비밀번호) 통과 필요, 로그인 후 상시 영역에 현재 계정 이름·등급 표시.
- AC-10.5 로그인 계정은 "계정 설정"에서 본인 비밀번호 변경 가능, 관리자 등급은 타 계정 비밀번호 강제 초기화 가능.
- AC-10.6 미인증 사용자는 어떤 등급 화면에도 접근 불가 — **현재 apps/admin(:3001)은 무인증 로컬 데모 상태이며, 이 FR은 인증 구현(`docs/analysis/05-work-orders.md` WO-3 흡수분)이 선행돼야 실효성이 생긴다.**
- AC-10.7 등급 이름·개수(최종 관리자/콘텐츠 관리자/검수 담당)는 예시 — **Q21 미확정**, 클라이언트 확인 필요.
