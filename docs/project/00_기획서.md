## 한 줄 요약

"AI 에이전트가 블로그를 운영하는 법을 보여주는 템플릿" 코드 위에, "AI 빌더 그룹 B2B 영업 사이트"
(포트폴리오·매칭·문의 웹사이트 + 관리자 시스템)를 실제 제품으로 전환한다.

## 제품

- **무엇**: AI 빌더 그룹(가제)의 영업용 웹사이트(랜딩) + 관리자 페이지.
- **왜**: 신규 브랜드라 포트폴리오가 없다. "저렴함"이 아니라 "일하는 방식 + 검증된 맞춤 개발자
  매칭"으로 신뢰를 얻어야 한다. CTA 하나로 전환이 크게 흔들린 실측 사례가 있어 트래킹이 필수다.
- **핵심 성공 조건**: ① 딸깍(AI로 대충 만든) 느낌이 나지 않는 디자인, ② 전환 추적 가능한 트래킹
  구조.

## 정보구조 (목표)

```
Home · Work(포트폴리오) · Insight(콘텐츠) · Eduinfo(교육) · 문의하기
관리자: 대시보드 · Builder · Work · Work Process · Insight · 설정 · 계정·권한
```

## v1 범위

- **포함**: Home, Work, Insight, Eduinfo, 문의하기(pluug 연동), 관리자(Insight 관리·빌더 관리·
  프로젝트 승인·계정 권한), GA 트래킹, SEO 테크니컬 세팅.
- **제외**: 3사 소개 페이지, AX 컨설팅, 관리자 매칭·CRM, GEO/AEO 별도 대응, 빌더 프로필 실제 기능
  (자산화 PDF·AI 추천 매칭).

## 지금 이 프로젝트(vdmp)의 위치

- 코드는 아직 "AI 에이전트 블로그 템플릿" 그대로다 — Work/Builder/Eduinfo 라우트·데이터 모델이
  없고, `apps/admin`은 무인증 블로그 CMS 수준이다.
- 디자인은 1안(`artifact/builder-group`)·2안 두 시안이 후보로 남아 있고, 통합 방향(Q18)이
  미확정이라 화면목록(IA)·화면설계는 확정할 수 없는 상태다(`02_화면목록_IA.md`, `05_화면설계.md`
  참조).
- 현재 착수 가능한 것은 데이터 모델·정책·기능명세 정리와, 기존 Blog 기능을 Insight로 단계적
  전환하는 것이다.
