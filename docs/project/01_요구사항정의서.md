## 1. 제품 개요

**제품**: AI 빌더 그룹(가제)의 영업용 웹사이트 — 랜딩 페이지 + 관리자 페이지.

**문제**
- 신규 브랜드라 내세울 포트폴리오가 없다.
- "마케팅비가 매출의 40% 이상을 먹는" 기존 교육 플랫폼 구조와 다른 방식으로 신뢰를 얻어야 한다.
- CTA 버튼 하나로 주간 문의가 10~20건 → 0건까지 떨어진 실측 사례가 있어(§9.2 근거), 트래킹 없이는
  무엇이 전환을 죽이는지 알 수 없다.
- "바이브 코딩으로 대충 찍어낸 느낌"이 나면 "바이브 코딩 외주를 믿고 맡기라"는 메시지 자체가 무너진다.

**목적**: 첫 화면에서 "바이브 코딩으로 외주를 받아주는 곳"임을 즉시 전달하고, 문의(리드)를
pluug(CRM)로 정확히 넘겨 실제 수주로 연결한다. Work(포트폴리오)·Insight(콘텐츠)·빌더 프로필로
포트폴리오 부재를 신뢰 자산으로 상쇄한다.

**핵심 가치 제안**: "포트폴리오 개수가 아니라, 일하는 방식과 검증된 맞춤 개발자 매칭." 저가 소구
대신 똑빌더 시스템 기반 체계성으로 품질을 보증한다.

**핵심 성공 조건** (전체를 관통하는 두 축)
1. 딸깍(AI로 대충 찍어낸) 느낌이 나지 않는 디자인
2. 전환을 추적할 수 있는 트래킹 구조

**타겟**
- 1차: 바이브 코딩 외주를 맡기고 싶은 스타트업/중소기업 프로젝트 발주 담당자
- 2차: 향후 프로필을 이력서처럼 쓰게 될 빌더(수료생) — 대기업 클라이언트 제출용, AI 추천 매칭용

## 2. 목표 & 성공지표 (KPI)

> 모든 수치는 기획서 시점의 가설이며, 실측 데이터로 기준선을 재설정한다.

| 구분 | 지표 | 목표(가설) | 측정 방법 |
| --- | --- | --- | --- |
| North Star | 주간 문의하기 제출 건수 | 평시 수준 유지·개선(주 10~20건) | GA 문의폼 제출 이벤트 카운트 |
| 전환 안정성 | 주요 CTA 요소 단위 클릭 추적 커버리지 | 100% | GA 이벤트 태깅 점검 |
| 유입 경로 | 유튜브 → Insight 전환율 | 베타 기준선 확보(첫 측정) | UTM 파라미터 기반 유튜브 스튜디오/GA 교차 확인 |
| 디자인 신뢰도(정성) | 목업 리뷰 시 "딸깍 느낌" 탈락 없이 통과 | 팀장 2인 승인 | 투표 금지, 총대 2인 결정 |
| 검색 노출 | 구글·네이버 기본 테크니컬 SEO 체크 통과 | 100% | Search Console / 네이버서치어드바이저 색인 확인 |
| 일정 준수 | 총 3주(제작 2주 + 세팅·이관 1주) 내 런칭 | 100% | 마일스톤 완료일 — ⚠️ 기산점 미정(Q5) |

## 3. 범위 (Scope)

### In Scope (v1)

- 홈 — 3사 소개 없이 "바이브 코딩 외주" 메시지 즉시 전달
- Work(포트폴리오) — 실제 수행 프로젝트 + 참여 빌더 연결
- Insight(콘텐츠/블로그) — 빌더 작성 글 → 빌더 프로필 연결
- Eduinfo(교육 콘텐츠) — 이솝 강의 영상 + PDF 자료 인덱스
- 문의하기 — pluug 폼 연동으로 리드 적재
- 관리자 페이지 — Insight 관리, 빌더 계정 관리, 빌더 업로드 프로젝트 승인, 계정·권한 관리
- GA 트래킹 — URL 슬러그 분기, 요소 단위 클릭 이벤트, UTM
- SEO 테크니컬 세팅 — 구글 + 네이버 기본
- 디자인 품질 게이트 — 섹션별 차별화된 인터랙션, 고퀄리티 에셋

### Out of Scope (v1 제외)

| 항목 | 결정 근거 |
| --- | --- |
| 3사(크몽·똑똑한 개발자·이솝 님) 소개 페이지 | D1 — 교육 플랫폼 홍보가 목적이 아님 |
| AX 컨설팅 콘텐츠/서비스 | D2 — 아직 서비스 자체가 없음, 다음 릴리즈에서 고도화 |
| 관리자 매칭 기능 · CRM | D3 — 리드는 pluug가 전담 |
| GEO/AEO 별도 대응 | D10 — 테크니컬 SEO 세팅까지만 |
| 빌더 프로필의 실제 기능(자산화 PDF, AI 추천 매칭) | Q8 — 아이디어 수준. v1은 IA까지만, 기능은 백로그 |

**릴리스 경계**: M1(IA + 디자인 목업 확정) → M2(퍼블리싱 + 관리자 + 연동 개발) → M3(세팅 + 이관).

## 4. 비기능 요구사항 (NFR)

| 구분 | 요구사항 | 검증 관점 |
| --- | --- | --- |
| 디자인 신뢰도("딸깍 방지") | 섹션마다 다른 인터랙션, 애니메이션 강약 조절, 동일 애니메이션 반복 금지 | 팀장 2인 목업 리뷰 통과 |
| 에셋 품질 | 저품질 에셋은 리터칭 후 반영, 목업은 최고 퀄리티 이미지 사용, 레퍼런스는 팀이 직접 픽 | 무드 유지 가이드 문서 동반 여부(A7) |
| UX 검토 | 참고 사이트 구조를 그대로 베끼지 않고 실제로 좋은 UX인지 자체 검토 | A6 검토 결과 문서화 |
| 전환 안정성 | 신규 UI 요소 추가가 문의 전환에 미치는 영향을 배포 전후로 확인 | 배포 전후 GA 전환 추이 비교 |
| 카피 원칙 | 상세는 `04_정책정의.md` §1 참조 | 카피 리뷰 시 원칙 위반 여부 체크 |
| 콘텐츠 진실성 | 상세는 `04_정책정의.md` §2 참조 | 게시 전 실적 사실관계 확인 |
| 반응형/호환성 | 데스크톱·모바일 기본 대응 | 주요 브라우저에서 핵심 플로우(홈→Work/Insight→문의하기) 확인 |
| 정보 접근성/SEO 정합성 | Work·Insight 상세를 모달로 보여주는 목업 패턴은 링크 공유·검색 색인 불가 — 실제 퍼블리싱 시 라우팅 페이지 병행 여부 결정 필요(Q15, Q17) | 배포 전 URL 접근성·색인 가능 여부 확인 |

## 5. 우선순위 (MoSCoW)

| 등급 | 항목 | 근거 |
| --- | --- | --- |
| **Must** | FR-1 홈, FR-2 Work(실제 프로젝트만), FR-4 문의하기+pluug 연동, FR-8 SEO/GA 트래킹, FR-5 Insight 관리(관리자 최소), NFR 디자인 신뢰도·에셋 품질·카피 원칙 | "핵심 성공 조건 두 가지" + 전환 루프(방문→신뢰→문의) 직결 |
| **Should** | FR-3 Insight(블로그), FR-6 유저(빌더) 관리+프로젝트 승인, FR-9 Eduinfo, FR-10 관리자 계정·등급·권한 관리 | 콘텐츠 축적·리드 소스 다변화에 필요하나 런칭 당일 필수는 아님. FR-10은 실제 인증 구현(WO-3)이 선행돼야 의미가 있음 |
| **Could** | FR-7 빌더 프로필(IA·와이어프레임만 — 목업에서는 Work 상세 모달로 상당 부분 선반영됨) | 마찰 감소·차별화 요소이나 v1 핵심 루프 밖. FR-2 모달과의 역할 정리 필요(Q17) |
| **Won't (v1)** | 3사 소개 페이지, AX 컨설팅, 관리자 매칭·CRM, GEO/AEO 별도 대응, 빌더 프로필 실제 기능 | 범위 통제 |
